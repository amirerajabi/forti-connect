IPsec on Windows works end to end: FortiConnect no longer hangs while setting up the VPN adapter, and company servers
behind the FortiGate answer through the tunnel.

FortiConnect 0.5.x updates itself to this version (Settings → Updates).

## Downloads

- Windows: `FortiConnect-Setup-0.5.2.exe` (includes OpenConnect)
- macOS (Apple silicon): `FortiConnect-0.5.2-mac-arm64.dmg`
- Linux: `FortiConnect-0.5.2-x86_64.AppImage`

## Fixes

- **IPsec connect stayed at "Setting up the VPN adapter".** The adapter was ready within seconds, but its "ready"
  message got mixed up with the first network packets; it is now always sent first.
- **The VPN address could not be set when FortiClient had used it last.** FortiClient's adapter keeps the address it
  got from the FortiGate; FortiConnect now moves it to its own adapter.
- The VPN address is usable the moment FortiConnect says Connected (no duplicate-address check on the VPN adapter).
- Updating the VPN helper is sturdier: the helper always starts again afterwards, even if an update fails.

The VPN helper is updated to version 8 the first time you connect (Windows asks for administrator rights once).

## Known limits

- New keys during a long IPsec connection are not supported yet: a tunnel may drop after about 12 hours and reconnect.

## Unsigned builds

On Windows, SmartScreen may warn on first run: choose **More info → Run anyway**. On macOS, right-click the app and
choose **Open** the first time; macOS copies announce updates instead of installing them.
