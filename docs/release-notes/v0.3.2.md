Connecting again after a network drop no longer fails once first.

FortiConnect 0.2.x and 0.3.x update themselves to this version (Settings → Updates).

## Downloads

- Windows: `FortiConnect-Setup-0.3.2.exe` (includes OpenConnect)
- macOS (Apple silicon): `FortiConnect-0.3.2-mac-arm64.dmg`
- Linux: `FortiConnect-0.3.2-x86_64.AppImage`

## Fixes

- **No failed first try after a drop.** When the network went down, the previous connection could not log out from
  the gateway and had to be ended forcibly. Windows was then still removing its network adapter, so the next connect
  failed once ("Could not open Wintun adapter") and used up a reconnect attempt. FortiConnect now tries again after
  a second, without counting it as an attempt.

## Unsigned builds

On Windows, SmartScreen may warn on first run: choose **More info → Run anyway**. On macOS, right-click the app and
choose **Open** the first time; macOS copies announce updates instead of installing them.
