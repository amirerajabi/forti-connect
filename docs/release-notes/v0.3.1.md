FortiConnect gets back on its own, and faster, after the network drops.

FortiConnect 0.2.x and 0.3.0 update themselves to this version (Settings → Updates).

## Downloads

- Windows: `FortiConnect-Setup-0.3.1.exe` (includes OpenConnect)
- macOS (Apple silicon): `FortiConnect-0.3.1-mac-arm64.dmg`
- Linux: `FortiConnect-0.3.1-x86_64.AppImage`

## Fixes

- **Back within seconds after a network drop.** Many FortiGates do not let a dropped session continue. With those,
  OpenConnect used to keep trying for up to 5 minutes while the VPN did nothing. FortiConnect now ends it right away
  and logs in again with your saved password as soon as the gateway answers.
- **Waits for the network instead of giving up.** While the gateway cannot be reached, FortiConnect checks every few
  seconds and Home says "Waiting for the network to come back…". This no longer uses up the 5 reconnect attempts, so
  an outage of any length ends in a connection.
- **Connecting no longer fails once after every disconnect** ("Could not open Wintun adapter"). On Windows the VPN
  helper now asks OpenConnect to stop cleanly, so it logs out, removes its routes and its adapter. The helper updates
  itself on your next connect: Windows asks for administrator rights once.

## Unsigned builds

On Windows, SmartScreen may warn on first run: choose **More info → Run anyway**. On macOS, right-click the app and
choose **Open** the first time; macOS copies announce updates instead of installing them.
